# ADR 0001 — XLSX 支持策略

- **状态**：已被 [ADR 0003](0003-csv-only-input.md) 取代（Superseded）——决策改为只收 CSV
- **日期**：2026-11-19
- **决策**：引入 `fflate`（仅解压）+ 自写解析层，而不是「不支持」或「引入 `xlsx`」
- **影响范围**：`loan_audit`（阶段 C）、`package.json` 依赖、README 的「零依赖」表述、验收用例

---

## 1. 背景

`loan_audit` 要做的事只有一件：用户把银行/网贷发的**还款计划表**丢进来，插件按严格口径重算，逐期对差，指出哪一期多收了钱。

问题在于这张表长什么样。用户手上几乎不会是 CSV——银行 App 导出、客户经理发微信、网银下载，默认都是 `.xlsx`。要求用户「先另存为 CSV」是一道真实的流失门槛，而且很多人不知道怎么存。

所以必须先回答：**这个插件要不要自己解析 `.xlsx`。**

## 2. 术语（给没参与讨论的人）

| 词 | 含义 |
|---|---|
| `.xlsx` | 一个 ZIP 包，里面是 XML。**不是**纯文本，不能按行切 |
| 共享字符串 | 重复文本只存一份，单元格存的是索引；不查表读出来是数字 |
| 合并单元格 | 一个值覆盖多行多列，其余格子在文件里是空的 |
| 日期序列号 | Excel 把日期存成数字（如 `46082` = 2026-03-01），靠 `styles.xml` 的格式还原 |
| 1900 / 1904 基准 | 两套纪元，差 1462 天；Mac 老文件用 1904，读错就整体偏 4 年 |
| 缓存值 | 公式单元格同时存「公式」和「上次算出的值」；文件没缓存过就只有一个公式 |

## 3. 三个选项

### 选项 A：不支持 XLSX，只读 CSV/TSV

- **做法**：README 写明「请另存为 CSV」，解析器只处理分隔文本。
- **优点**：零依赖、零解析风险、半天写完、永远不会因为文件格式变化而坏。
- **代价**：真实的流失门槛。用户拖进 `.xlsx` 会被明确拒绝，然后大概率就没有然后了。
- **失败模式**：不是技术失败，是产品失败。

### 选项 B：引入 `xlsx`（SheetJS）或 `exceljs`

- **做法**：`npm i xlsx`，一行 `XLSX.read()` 拿到二维数组。
- **优点**：功能最全，一行代码解决，社区资料多。
- **代价**（实测，非印象）：
  - npm 上的 `xlsx@0.18.5` 带 **7 个运行时依赖**：`cfb`、`ssf`、`wmf`、`word`、`crc-32`、`adler-32`、`codepage`。其中 `wmf`、`word` 是图像/文档解析器，我们完全用不到，但都要进供应链。
  - 解压后 **7.5 MB**。
  - npm 渠道自 **2022-03** 起未再更新；公开通告里的两个已知问题（原型污染、ReDoS）的修复版本只在 SheetJS 自有渠道发布，npm 上仍是受影响版本。
  - `exceljs` 同样带一串依赖（含 `archiver`、`unzipper`），体积更大。
- **失败模式**：为了读一张表，把一个 7 依赖、7.5 MB、npm 上停更的解析器装进用户的 DSH——而这个插件的定位本来就是「干净、可审计」。

### 选项 C：`fflate` 解压 + 自写最小解析层（**选中**）

- **做法**：`fflate.unzipSync()` 把 ZIP 解开，自己读 `workbook.xml` / `sharedStrings.xml` / `styles.xml` / `worksheet*.xml`，产出二维数组。
- **优点**：
  - `fflate@0.8.3`：MIT、**零运行时依赖**、无 `install`/`postinstall` 脚本（只有 `prepack`，发布时才跑，安装方不执行）、ESM 入口约 30 KB。
  - 只做「解压」一件事，不管公式、不管样式引擎、不管写文件——**我们只读，且只读我们要的那几列**。
  - 解析行为完全可控：遇到合并单元格、日期序列号该怎么处理，由我们决定并写进第 5 节，而不是交给别人的默认值。
- **代价**：
  - 约 300–400 行解析代码要自己写、自己测、自己被真实表格打。
  - 引入 1 个运行时依赖，「零依赖」这个卖点要改口径（见第 9 节）。
  - 边界情况（合并单元格、1904 基准、无缓存公式）的 bug 归我们，不归上游。
- **失败模式**：真实表格千奇百怪，解析器可能需要持续打补丁；如果 bug 密度失控，就要回到选项 A 或 B（见第 10 节的推翻条件）。

## 4. 决策

**选 C。**

四条理由，按权重排序：

1. **风险面**：1 个零依赖、单一职责的 MIT 包，对比 7 个依赖、7.5 MB、npm 停更的包。这个插件的全部价值是「可信」，不值得为省 300 行代码把供应链搞脏。
2. **职责匹配**：我们要的是「取值」，不是「电子表格引擎」。fflate 只解压，剩下的语义由我们定义——这正是第 5 节能写成承诺表的前提。
3. **可控的失败**：自己写的解析器出错，能定位到行、能加 fixture、能在一小时内修；别人的解析器出错，只能升级、等待或绕。
4. **版本便宜**：`fflate` 的 API 面极小（`unzipSync` + `strFromU8`），十年不升级也不会坏。

**不选 A** 的理由：把流失门槛转嫁给用户，等于不给这个工具机会。
**不选 B** 的理由：见上，代价与收益不成比例。

## 5. 承诺支持到什么程度（bug 的裁判依据）

这张表是契约：表内行为是**承诺**，表外行为是**未定义**。任何 issue 先对照这张表判断是 bug 还是边界外。

| 情况 | 承诺 | 超出时怎么办 |
|---|---|---|
| 文件类型 | `.xlsx`、`.csv`、`.tsv` | 其他类型明确报错并说明原因 |
| 旧版 `.xls`（二进制 BIFF） | **不支持** | 报错：「请用 Excel/WPS 另存为 .xlsx 或 .csv」 |
| 加密 / 带密码的文件 | **不支持** | 报错：「请先解除密码保护」 |
| 文件大小 | ≤ 10 MB；解压后总量 ≤ 100 MB | 超限报错，不做「尽力而为」 |
| 工作表选择 | 默认选第一个「像还款计划」的表（含期数/应还/本金/利息任一表头特征）；可用 `sheet` 参数指定名称或序号 | 自动判断失败时，返回所有工作表名，让调用方指定 |
| 表头行 | 在前 10 行内探测；可用 `headerRow` 从 1 开始强制指定 | 探测失败：报错并回显前 10 行原文，不做猜测 |
| 合并单元格 | 仅支持**表头行**的横向合并：把合并区首列的值广播到其覆盖的各列，并在 `warnings` 里记一条 | 数据区出现合并：按「首列有值、其余为空」读取，并记 `warnings` |
| 日期序列号 | 支持 1900 与 1904 两种基准；识别常见的日期 `numFmt`（`yyyy-mm-dd`、`yyyy/m/d`、中文日期等） | 识别不了时按**数字原样**输出，字段名后缀 `Raw`，并记 `warnings` |
| 公式单元格 | 有缓存值就用缓存值；**没有缓存值则视为空**，记 `warnings` 并提示「在 Excel 里重新保存一次以生成计算值」 | 不内置公式引擎，永不计算 |
| 金额精度 | 单元格里的金额只做一次 `toCents` 转换，之后全程整数分（与 `lib/money.mjs` 一致） | 出现超过 2 位小数时按四舍五入到分，记 `warnings` |
| 空行 / 空列 | 表头之前的空行跳过；表头之后的整行空行跳过；尾部空列忽略 | 中间的行内空格按空字符串处理，不跳行 |
| 多行表头（两层） | **不支持**：只取探测到的那一行 | 需要时用 `headerRow` 手工指定第二层 |
| 数值型字符串 | `"1,234.56"`、`"¥1,234.56"`、`"1,234.56元"` 均解析为数值 | 其他修饰字符按解析失败计，该期记 `warnings` |
| 输入编码 | **UTF-8 / GBK / GB18030 自动探测**：有 BOM 按 BOM；无 BOM 依次试解，取第一个能完整解码的。解码走 Node 内置 `TextDecoder`，**不引入依赖** | 三种编码都失败时报错，并列出已尝试的编码 |

**共同的兜底原则**：解析出的每一期都带 `warnings`；只要有一期无法解释，`loan_audit` 的结论就必须标注「部分数据未解析」，**绝不**静默丢弃一行然后给出一个看起来干净的总额。

## 6. 接口契约（对 `loan_audit` 的约束）

输入新增三个可选参数：

```ts
{
  path?: string,        // 工作区里的文件路径（与 csvText 二选一）
  csvText?: string,     // 直接粘贴的表格文本，兜底
  sheet?: string | number,  // 工作表名或 1 起的序号
  headerRow?: number,   // 表头所在行，1 起
}
```

返回的 `data` 必须包含：

```ts
{
  source: { kind: 'xlsx' | 'csv' | 'tsv', sheets: string[], sheetUsed: string, headerRow: number },
  rows: Array<{ period: number, dueCents: number, principalCents: number, interestCents: number, balanceCents: number, warnings: string[] }>,
  warnings: string[],   // 文件级问题：合并单元格、无缓存公式、舍入等
  totals: { ... },
}
```

`warnings` 非空时，Markdown 结论里必须出现对应的提示行——**不允许把警告留在结构化数据里而人看不到**。

## 7. 代价与风险

| 风险 | 缓解 |
|---|---|
| 依赖本身出问题（漏洞/投毒） | 锁到 `^0.8.3`；升级必须过第 8 节的验收用例；`npm audit` 纳入发布前检查 |
| 解析器 bug 密度高 | 先攒 3 个真实样本再写代码（见第 8 节），不为想象中的表格写分支 |
| 包体积增大 | 只 import `fflate` 的 ESM 入口，不引 UMD；打包后增量 < 50 KB |
| 「零依赖」卖点受损 | README 主动披露「一个依赖、为什么、它是什么」，把透明当卖点（见第 9 节） |
| 用户拿 `.xls` 或加密文件来 | 明确报错 + 给操作指引，不猜、不降级 |

## 8. 验收标准

实现必须满足：

1. **真实样本**：至少 3 份脱敏的真实还款计划表（不同银行/不同还款方式），逐期与银行数字对差，差异必须为 0 或被 `warnings` 解释。
2. **合成样本**：覆盖第 5 节每一行——合并表头、1904 基准、公式无缓存、多工作表、表头在第 5 行、GBK 编码的 CSV、`.xls`、加密文件、超限文件。
3. **回归**：`npm test` 全绿且不联网。
4. **恶意输入**：zip bomb（解压后 > 100 MB）、路径穿越条目（`../../etc/passwd`）、畸形 XML，必须报错而不是崩溃或写盘。
5. **打包**：`npm pack` 后装进空目录能加载，依赖随包安装，`files` 白名单不遗漏。

## 9. 连带改动（已随本 ADR 落实）

- README「约定」新增一条：依赖只有 `fflate` 一个，并链接回本 ADR。README 从未出现「零依赖」字样，无需改口径。
- README 工具表里 `loan_audit` 的输入从「（CSV）」改为「（`.xlsx` / `.csv` / `.tsv`）」。
- `package.json` 的 `description` 去掉「骨架 / 未实现」的过期说法。
- 阶段 C 的计划（C1「先不做 XLSX」）作废，XLSX 从第一天就在 `loan_audit` 范围内。

**尚未落实**：`package.json` 的 `dependencies` 里还没有 `fflate`。这是有意的——依赖在使用它的代码（`lib/xlsx.mjs`）落地的同一次提交里再加，避免仓库里挂一个没人 import 的依赖。届时版本锁 `^0.8.3`。

## 10. 什么情况下应该推翻这个决策

满足任意一条就重开讨论，不要惯性维护：

1. `fflate` 出现未修复的安全通告，或停止维护超过 18 个月。
2. 自写解析层超过 ~600 行（不含测试），说明复杂度已经失控，应回到选项 A 并诚实告知用户。
3. 真实用户样本里，**超过 30% 的文件解析失败**且无法用「另存为 CSV」绕过。
4. DSH 官方提供了稳定的表格读取 API（届时不该重复实现，应直接调用）。
5. 上线 3 个月后看数据：几乎没有 `.xlsx` 输入（全是粘贴文本）→ 降级为零依赖，删掉解析层。

## 附：为什么不是「让模型先用 office 插件转成 CSV」

曾考虑过这条路径：DSH 里已装 `dsh-univer-office`，模型可以自己读 xlsx 再转文本，插件保持零依赖。

否决原因：

- 依赖用户装了某个**别的**插件，且版本兼容——插件的可用性不该由第三方决定。
- 多一步模型推理，就多一次转写错误的机会，而「数字转写错误」正是本插件要消灭的东西。
- 转换发生在模型上下文里，大表会吃掉大量 token；插件内部解析不占上下文。

记录在此，避免以后重复讨论。
